# 第三组团队分工与协作

成员：陆春雨（组长）、宁耀硕、胡晰瑞。

本组选择课程设计的“体重预测算法”扩展功能，并完成睡姿识别、身体部位划分和实时可视化三项基础工作。下表定义的是后续开发责任与交接边界；每位成员只对自己实际完成的工作提交代码、文档和会话记录。

## 二、模块接口与交接

1. 宁耀硕交付统一的数据格式、标签字典、用户级训练/测试名单、数据增强说明和随机种子。训练与测试必须按用户隔离，不能将同一用户的相邻帧同时用于训练和测试。
2. 宁耀硕向陆春雨提供睡姿模型的输入尺寸、预处理方法、类别顺序和推理输出；胡晰瑞按同一数据格式使用压力帧。
3. 胡晰瑞向陆春雨提供区域划分和体重模型的输入输出、区间边界、空载校正规则及指标文件。体重展示应分别给出连续预测值和区间结果。
4. 陆春雨提供稳定的接口字段和回放流程。模型或字段变更须在同一 PR 中更新接口文档和前端调用。
5. 三人联调时，任何指标只引用对应提交版本自动生成的结果，并标明单帧、时间窗口或用户级评价口径。

## 三、协作流程

1. 在仓库创建 Issue，写清目标、负责人、涉及模块、验收条件和依赖。
2. 从最新 `main` 创建个人分支。分支名称建议使用 `data/`、`model/`、`api/`、`ui/` 或 `docs/` 前缀。
3. 完成一项可验证的改动后提交。提交信息同样使用上述前缀，并准确描述实际工作。
4. 创建 Pull Request，关联 Issue，附运行命令、测试结果、模型指标或页面截图。分工表中的交叉相关成员负责审查。
5. 审查通过后合并到 `main`；其他成员同步主分支后继续工作。共享文件冲突由修改双方共同解决。
6. 最终提交前，全体从干净环境按运行说明完成一次训练、推理和可视化演练，记录最终提交 SHA。

## 四、数据、代码与材料管理

- 原始数据仅使用课程提供的数据集；数据增强方法、数据比例和随机种子要记录在项目文档中。
- 公开仓库不提交原始数据、`node_modules`、本地环境、模型大文件、密钥或个人隐私信息。
- 课程要求每组提供代码、团队仓库的 git log 和项目管理记录；每人提供一份个人报告与完整 AI 会话记录（Markdown 或 JSON）。个人会话记录须保留真实问题、回答和修改过程，并在提交前自行检查隐私信息。
- 气囊展示应依据课程给出的气囊和传感器对应关系；若使用离线回放或模拟控制，演示页面与报告中须如实说明。
